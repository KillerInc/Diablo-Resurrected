# GPU interface and HD UI resources, 0.4.15-pre

The existing executable now draws UI sprites, fonts, outlines, cached surface
sections, rectangles and lines through an indexed GPU UI pipeline. Glyphs and
native occupancy/index data are decoded once and uploaded in the frame batch;
no wait is issued for each new letter. Text layout and interface/game logic
remain on the CPU. Original indexed drawing remains available for Classic,
virtual gamepad, native screenshots and unsupported/raw writers.

UI draws keep their original order with world actors. Clipping uses the original
surface region; opaque palette index zero remains distinct from transparency.
Palette translations and fades resolve against the live palette at presentation,
including changes after commands were queued. Inventory-slot colour shifts are
GPU palette transformations over the relevant UI regions. Cursor-only redraws
remove the old cursor commands and restore underlying coverage.

The background, health, mana/spell, buttons and belt retain separate GPU command
caches. Only dirty components rebuild. Static backing buffers reuse GPU index
textures; off-screen edits invalidate those entries and the HUD command cache.
Localized button pixels baked into the original panel remain native where they
differ from its HD source. Hover information and other transient content remain
outside the retained layer.

A CPU UI raster fallback remains for direct writers such as automap strokes.
When it is unused, the renderer skips clearing and uploading the full-screen
CPU UI image; the terrain shader bypasses that empty overlay. Missing resources
retain the native indexed UI rather than introducing PNG loading.

## Private graphics pack

The staged installation adds 193 prepared UI resources on 195 BC7 pages:
control panels, data/inventory artwork, item icons, PCX menu/title artwork and
loading/quotation screens. They use 4x width and height, or 16x native pixels.
All 193 resources and 195 pages remain user-supplied private artwork. They are available
on demand; unused/obsolete screen assets are not preloaded or made into new UI.
The complete UI set is 677,920,768 texture bytes if all resources were resident.
The combined index has 1,300 sheets / 2,974 pages / 9,615,097,856 texture bytes
across every class and resource. This is not the game's active VRAM residency.

CEL groups retain their original frame IDs, variable widths and bottom alignment.
Prepared PCX resources use 128x128 native blocks; the renderer maps each runtime
animation frame back into the original source image and clips across block
boundaries. Canonical source palettes preserve colour cycling, translations and
fades without recolouring the artwork incorrectly. Fonts/support artwork that
have no compiled replacement use cached native indexed GPU textures.

The sole compiled metadata source remains HD/sprites.gpus, cached until process
exit. Installation preserves all 1,107 previous records and every previous BC7
page, the layout CSV, authoring PNGs, preferences and saves. The installer refuses
to replace unknown art, backs up the old index and adds only the validated UI
pages. Executable installation and backups are separate. No PNGs or per-sheet
metadata are installed. Restart after changing the root index.

## Validation

Owned synthetic GPU readbacks cover PCX animation frames across block boundaries,
CEL alignment, opaque zero, TRNs, palette fades, native/HD fallback, localized
backing pixels, outlines, clipping, ordered transparency, inventory tinting,
retained HUD replay/dirty invalidation and source-buffer edit invalidation.
Actor/terrain readbacks, provider/source metadata and saved-mode checks also run.
Installer tests verify record/layout preservation and rejection of unknown art.

The frontend smoke helper captures the real title/logo animation and main menu
with isolated saves/settings, music/effects/cues muted and the left display
selected. These private captures are reviewed separately from FPS comparisons.
D1R_GPU_UI=0 restores the comparison path. D1R_FRAME_DUMP_UI enables frontend
captures explicitly; normal captures and preferences retain their prior policy.
CPU submission measurements are wall timings, not GPU execution times.

Standalone screens begin a new command batch after presentation, while nested
dialog layers share the current batch. Loading/progress screens retain their
background commands between foreground updates. Credits explicitly redraw their
batch as they scroll, and movie playback clears menu resources before starting.
Inactive-window presentation also closes the batch to avoid accumulating draws.

## Measured cost

Sequential, capture-free 900-tick copied-save runs excluded the first active
interval. The previous executable measured 156.89 / 152.09 FPS; this build with
GPU UI and HD art measured 150.59 / 151.97 FPS. An open-inventory run measured
135.48 FPS before and 114.24 FPS with HD UI. The same new build with GPU UI
disabled measured 157.52 FPS. These are fixed-scene comparisons, not a general
FPS guarantee. This change delivers GPU UI and HD artwork, not a demonstrated
speed increase. Additional UI draw/control submissions are a remaining cost.
The profiled scene still used the CPU UI raster fallback, so empty-overlay
elimination did not apply there. No GPU execution timings were measured.
