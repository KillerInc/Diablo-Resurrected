# Project working agreement

- GitHub is the durable record of this project. Keep completed source changes, tests, build configuration and validation documentation committed and pushed to the working branch. Report the remote commit rather than leaving the only copy in a local working tree.
- Local source checkouts and build files are temporary tools for implementation and testing. Do not install source into the game directory or keep extra source copies as deliverables. Keep a checkout only while it is needed for active work or validation.
- The installed graphics sheets are user-supplied reference/test inputs. Never commit or upload them. Do not include screenshots/captures containing that artwork, extracted original game data or saves in repository commits or public build artifacts. Synthetic test fixtures and the repository's existing open-source engine assets remain suitable for version control.
- Preserve installed game data, sheets, preferences and saves. Back up an installed executable before replacing it with a tested build.

- Since 0.4.3-pre, `HD/layouts.csv` is the only runtime layout source. It is cached until process exit; F10 does not reload it. Do not install individual `.layout` files into the game HD tree. Update the CSV atomically using `tools/hd_layouts.py` helpers and verify PNG hashes/anchors. Offline render outputs and private backups may retain sidecars. Legacy install scripts must be adapted before reuse.

- Since 0.4.4-pre, initial SDL3 save/new-game loading preloads and session-pins all installed sheets for the selected sprite class. Preserve pins across F10/level/display resets and release them on game exit; keep MPQ discovery serial and PNG workers bounded. Validation must check resident count/bytes, no warm player redecodes, reference-save outcomes, and current PNG/CSV hashes.

- Since 0.4.5-pre, F11 toggles the performance overlay and active gameplay emits interval metrics to the config-directory performance.csv. Preserve loading/inactive exclusions, CPU/RAM versus GPU/VRAM labeling, and F10/player cache behavior. Validate CSV values and F11 toggles alongside reference replays before installing renderer updates.

- Since 0.4.6-pre, the installed Warrior class has 255 compiled native-4x BC7 GPU sheets. Preserve original PNGs and HD/layouts.csv; GPU frame records carry crop/page coordinates while logical anchors still come from the single cached CSV. Keep pages bound to their metadata provider and resident across F10/levels; release class pages on game exit. Preserve Classic/CPU and virtual-gamepad compatibility. Do not retain full CPU player RGBA when compiled resources are available. Validate actual GPU draws, synthetic native-resolution/lighting/occlusion readback, warm-upload counts, two reference saves, UI and source hashes before installing.
- Run test audio with D1R_TEST_AUDIO_GAIN=0.5 (tools/run_gpu_replay.ps1 does this). Never reduce the user's normal saved volume settings for test convenience.
- Graphics replays must also mute music, effects and cues in their isolated test configuration. Keep the user's normal game settings and Windows audio levels unchanged; do not run audible background game tests unless the user explicitly requests them.

- Since 0.4.7-pre, `HD/sprites.gpus` is the sole runtime compiled-sheet index, cached per provider until process exit. Keep shared defaults in the index with explicit per-sheet exceptions; do not restore individual runtime `.gpus` reads. Finalize the index after parallel encoders finish. Preserve BC7 page hashes and back up retired metadata during installation.

- Since 0.4.8-pre, SDL3 HD world sprites are BC7-only, including monsters and missiles. This supersedes the older CPU PNG fallback policy: retain Classic pixels when compiled resources are unavailable. Preserve authoring PNGs and the layout CSV, discover player-class sheets from the compiled index, and avoid duplicate mounts of the same physical pack. Validate every compiled record through the GPU loader with no HD PNGs in the test pack, alongside the existing renderer checks. F10 and the Graphics `HD Graphics` toggle share a saved setting; startup restores it. Replay tests must not alter normal settings.

- Since 0.4.9-pre, HD uses a retained main-HUD backing layer beneath transient UI. Preserve component invalidation, palette/size/position invalidation, cursor restoration and Classic rendering. Do not cache menus, hover text or cursor pixels into the HUD. Batched world raster spans and spatial GPU coverage bins must preserve exact scalar blend/occlusion results.
- The user's second monitor is to the left. Visible graphics tests must launch there directly and remain muted. The replay tools set `D1R_TEST_DISPLAY=left`; test builds fail explicitly if that display is unavailable rather than opening on the primary monitor. Normal launches do not change display placement.
- Since 0.4.10-pre, optional `D1R_CPU_PROFILE_LOG` records detailed CPU-stage wall timings separately from the normal performance log. Keep profiling opt-in and exclude loading/inactive intervals. FPS comparisons must run sequentially with copied saves, no frame capture, fixed inputs/settings and repeated controls. Preserve the raw-UI fallback when skipping unchanged rows/blocks; test block edges, clipping and equal-color raster coverage. Do not present CPU command/submission timing as GPU execution time.
- The private MPQ-art pack prepared on 2026-10-31 contains 285 additional CEL/PCX resources at 4x dimensions (16x pixel count), including 8,999 terrain microcells. It is not installed or wired into terrain/UI drawing yet. Keep raw palettes, indices, source-frame IDs and PCX block-layout metadata; preserve native floor/foliage order and frame remapping during integration. Never replace the installed index with a preparation-only pack. Validate terrain/CEL exports against the engine's native decoder. Optional solid-block BC7 reuse must remain bit-exact with the existing encoder and fall back for nonuniform blocks.

- Since 0.4.11-pre, five prepared terrain atlases (8,999 microcells, 12 BC7 pages) are installed and drawn by the SDL3/D3D12 GPU background path. The combined runtime index contains 1,107 sheets; the rest of the 285-resource preparation pack remains private and inactive. Preserve original frame IDs, split floor/foliage origins, palette aliases, per-pixel lighting, ordered translucent walls, affine UI composition, foreground actor coverage and missing-terrain fallback. Keep terrain caches across F10/display/level changes and release references at game exit. Validate GPU readback, two save outcomes, UI transitions, zero warm player uploads, PNG-free loading and sequential capture-free performance controls before further renderer installs. D1R_GPU_TERRAIN=0 selects the previous background path for comparisons; normal launches enable GPU terrain when its compiled material exists.

- Since 0.4.12-pre, supported HD terrain uses cached native tile runs with GPU palette lighting and indexed frame presentation. Preserve custom-light-table, missing-material, Classic and virtual-gamepad fallbacks; native screenshots temporarily repaint indexed pixels. Keep BC7 page transfers separate from batched per-frame actor-control uploads. D1R_GPU_TILE_COMMANDS=0 and D1R_GPU_INDEXED_PRESENT=0 independently select the comparison paths. Validate odd-width row pitches, zoom, wall/UI order and warm residency before installing.

- Since 0.4.13-pre, GPU actors share one ordered render pass and retain per-slot palette textures when all colour bytes match. Preserve mutable palette/TRN invalidation, translucent overlap order, actor/page resource lifetime and Classic fallback. D1R_GPU_ACTOR_BATCH=0 restores per-actor passes and unconditional palette transfers for comparison; D1R_PROFILE_HD logs cumulative actor passes, palette transfers and control bytes.

- Since 0.4.14-pre, GPU terrain resolves compact ordered row spans through per-row 32-pixel bins instead of expanding CPU per-pixel owner/index/blend grids. Preserve original indices, custom-table/native fallback writes, newest-to-oldest alpha order, last-opaque truncation, bin boundaries, lighting and actor coverage. D1R_GPU_TERRAIN_SPANS=0 retains the previous pixel-grid path for comparison. Native screenshot and virtual-gamepad fallbacks remain required.
